# PLAN.md — 脉动阵列矩阵乘法器演进计划

> 本文档是项目演进路线图。每个阶段完成后更新状态，AI 按顺序推进。

## 总体思路

```
Phase 0: 验证闭环        → 从"写了没跑"到"跑通跑稳"（最高优先级）
Phase 1: 补短板          → 让现有设计健壮可靠
Phase 2: 工程化          → lint、CI、文档，专业基础设施
Phase 3: 性能提升        → 吞吐量和效率优化
Phase 4: 功能扩展        → 更多运算模式
Phase 5: 系统集成        → 标准接口，接入 SoC
Phase 6: 高级数据类型    → 浮点、定点、混合精度
Phase 7: 应用层          → CNN、Transformer 等实际场景
```

**核心原则：先验证，再优化，最后扩展。没有验证闭环的代码不可信。**

## Phase 3: 性能提升

### 3.1 双缓冲 (Double Buffering)
- **目标**：一组数据在计算，另一组同时加载，消除加载等待
- **改动**：增加两组输入缓冲，交替切换；FSM 增加 buffer 选择
- **验证**：对比单缓冲和双缓冲的吞吐量（cycles per matrix）
- **复杂度**：中
- **预计**：3-4 小时
- **状态**：⬜ 未开始
- **依赖**：0.3

### 3.2 PE 内部流水线化
- **目标**：拆分 PE 内的乘法和累加为两级流水线，提高最大时钟频率
- **改动**：`pe.v` 增加一级流水线寄存器
- **代价**：K_DIM 额外 1 周期延迟，需要调整数据对齐
- **验证**：时序分析 + 功能仿真
- **复杂度**：中
- **预计**：2-3 小时
- **状态**：⬜ 未开始
- **依赖**：0.1

### 3.3 性能计数器增强
- **目标**：统计 PE 利用率、空闲周期数、实际 GOPs
- **指标**：
  - `active_pe_cycles`：PE 实际在做乘累加的周期数
  - `total_cycles`：从 start 到 done 的总周期数
  - `pe_utilization` = active_pe_cycles / (M×N×total_cycles)
  - `throughput_gops` = (2×M×N×K) / (total_cycles × clock_period)
- **改动**：增加计数器寄存器 + 读出接口
- **验证**：对比理论值
- **复杂度**：低
- **预计**：1-2 小时
- **状态**：⬜ 未开始
- **依赖**：0.1

### 3.4 时钟门控 (Clock Gating)
- **目标**：空闲 PE 关闭时钟，降低动态功耗
- **改动**：PE 增加 clock enable，idle 行/列关时钟
- **验证**：功能不变 + 功耗对比（需要综合工具）
- **复杂度**：中
- **预计**：2 小时
- **状态**：⬜ 未开始
- **依赖**：5.3

### 3.5 数据流优化分析
- **目标**：量化分析不同数据流模式的带宽需求
- **分析内容**：
  - 当前 Output Stationary 模式的带宽瓶颈
  - 对比 Weight Stationary / Row Stationary 的理论吞吐量
  - SRAM 带宽需求计算
  - PE 利用率上界分析
- **产出**：`docs/dataflow_analysis.md`
- **复杂度**：低
- **预计**：2 小时
- **状态**：⬜ 未开始

## Phase 4: 功能扩展

- **目标**：支持 `A × B`、`A^T × B`、`A × B^T`、`A^T × B^T` 四种模式

### 4.2 矩阵加法模式
- **目标**：复用 PE 阵列做 element-wise 加法 `C = A + B`
- **改动**：PE 增加 `mode` 选择（MAC / ADD），FSM 简化为单周期
- **验证**：加法模式正确性
- **复杂度**：低
- **预计**：1-2 小时
- **状态**：⬜ 未开始
- **依赖**：0.1

### 4.3 向量-矩阵乘法
- **目标**：`y = v × M`，其中 v 是 1×K 向量，M 是 K×N 矩阵
- **改动**：只用第一行 PE，其余行旁路
- **验证**：对比标准矩阵乘法结果
- **复杂度**：低
- **预计**：1 小时
- **状态**：⬜ 未开始
- **依赖**：0.1

### 4.4 权重驻留模式 (Weight Stationary)
- **目标**：把 B 矩阵预加载到 PE 的寄存器中，只流式输入 A
- **用途**：CNN 推理（权重固定，输入流式）、Transformer 注意力（Q×K^T 重复计算）
- **改动**：
  - PE 增加 `weight_reg` 寄存器 + `weight_load` 模式
  - FSM 增加 `S_LOAD_WEIGHT` 状态
  - 增加 `weight_en` 控制信号
- **验证**：加载权重后多次流式输入不同 A，验证结果
- **复杂度**：高
- **预计**：4-5 小时
- **状态**：⬜ 未开始
- **依赖**：0.1, 3.1

### 4.5 分块计算 (Tiling)
- **目标**：大矩阵自动拆分成阵列能处理的小块，分批计算后拼接
- **改动**：上层 `systolic_array_tiled.v` wrapper 负责分块、调度、结果拼接
- **方案**：
  - 将 C = A×B 拆成 C[i][j] = Σ_t A[i][t] × B[t][j]
  - 每个子块用阵列计算一次
  - 结果累加到片上 SRAM
- **验证**：16×16 矩阵用 4×4 阵列计算，对比直接乘法结果
- **复杂度**：高
- **预计**：5-6 小时
- **状态**：⬜ 未开始
- **依赖**：4.4, 5.1

### 5.2 AXI-Lite 配置接口
- **目标**：运行时通过寄存器配置矩阵大小、模式选择、状态读取
- **寄存器映射**：
  ```
  0x00: CTRL        (start, stop, reset)
  0x04: STATUS      (busy, done, overflow)
  0x08: DIM_M       (矩阵 M 维度)
  0x0C: DIM_K       (矩阵 K 维度)
  0x10: DIM_N       (矩阵 N 维度)
  0x14: MODE        (乘法/加法/转置模式)
  0x18: CYCLE_COUNT (只读)
  0x1C: OVFLOW_COUNT(只读)
  ```
- **改动**：新建 `src/axi_lite_slave.v`
- **验证**：Cocotb 读写寄存器

### 6.3 BFloat16 支持
- **目标**：Google BFloat16 格式（与 FP32 同指数范围，训练友好）
- **改动**：类似 FP16，但指数 8-bit、尾数 7-bit，硬件更简单
- **验证**：对比 PyTorch bfloat16 结果
- **复杂度**：高
- **预计**：6-8 小时
- **状态**：⬜ 未开始
- **依赖**：6.2

### 6.4 混合精度模式
- **目标**：INT8 输入 × FP16 累加，或 INT4 输入 × INT8 累加
- **用途**：量化推理常用组合（INT8 权重 + INT8 激活，FP16 累加防溢出）
- **改动**：PE 的 DATA_WIDTH 和 ACCUM_WIDTH 支持不同数据类型
- **验证**：混合精度精度测试
- **复杂度**：中
- **预计**：3-4 小时
- **状态**：⬜ 未开始
- **依赖**：6.1, 6.2

### 6.5 多阵列并行
- **目标**：多个子阵列并行计算，提升吞吐量
- **改动**：顶层 wrapper 管理多个 systolic_array 实例
- **方案**：

- **复杂度**：高
- **预计**：6-8 小时

- **依赖**：4.5, 5.1

## Phase 7: 应用层

> 脉动阵列本身是计算核心，但缺少应用层包装。以下方向让它从"一个模块"变成"一个加速器"。

### 7.1 CNN 推理加速器
- **目标**：完整的 CNN 卷积层推理 pipeline
- **流程**：
  ```
  输入特征图 → im2col 转矩阵 → 脉动阵列乘法 → 加偏置 → 激活函数(ReLU) → 输出特征图
  ```
- **改动**：
  - 新建 `src/im2col.v`：将卷积窗口展开成矩阵行
  - 新建 `src/bias_add.v`：结果加偏置
  - 新建 `src/relu.v`：ReLU 激活
  - 新建 `src/cnn_layer.v`：顶层 pipeline wrapper
- **验证**：用一个 3×3 卷积层对比 PyTorch 结果
- **复杂度**：高
- **预计**：8-10 小时
- **状态**：⬜ 未开始
- **依赖**：4.4, 5.1

### 7.2 Transformer 注意力加速
- **目标**：Attention(Q,K,V) = softmax(Q×K^T / √d) × V 的矩阵乘法部分
- **改动**：
  - 权重驻留模式用于 K^T（多次查询同一 K）
  - 分块计算用于长序列
  - 可选：集成 softmax 硬件
- **验证**：对比 PyTorch `torch.nn.functional.scaled_dot_product_attention`
- **复杂度**：高
- **预计**：10-12 小时
- **状态**：⬜ 未开始
- **依赖**：4.4, 4.5, 6.2

### 7.3 矩阵分解加速
- **目标**：LU/QR/Cholesky 分解的核心操作是矩阵乘法和向量运算
- **改动**：上层状态机调度多次矩阵乘法 + 前代/回代
- **验证**：对比 NumPy `scipy.linalg.lu/qr`
- **复杂度**：高
- **预计**：8-10 小时
- **状态**：⬜ 未开始
- **依赖**：4.3, 4.5
