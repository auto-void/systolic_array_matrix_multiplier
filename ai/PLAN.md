# PLAN.md — 脉动阵列矩阵乘法器演进计划

> 本文档是项目演进路线图。每个阶段完成后更新状态，AI 按顺序推进。

## 总体思路

```
Phase 1: 补短板        → 让现有设计健壮可靠
Phase 2: 性能提升      → 吞吐量和效率优化
Phase 3: 功能扩展      → 更多运算模式
Phase 4: 系统集成      → 标准接口，接入 SoC
Phase 5: 高级特性      → 浮点、高级数据流
```

---

## Phase 1: 补短板（让现有设计可靠）

### 1.1 溢出检测与饱和运算
- **目标**：累加器溢出时 clamp 到 `ACCUM_WIDTH` 的最大/最小值，而不是 wrap
- **改动**：`pe.v` 增加溢出检测逻辑，饱和输出
- **验证**：添加溢出边界测试用例
- **复杂度**：低
- **预计**：1-2 小时
- **状态**：✅ 完成

### 1.2 结果保持与读出接口
- **目标**：计算完成后结果保持不变，提供地址选择读出（不用一次性全拿）
- **改动**：`systolic_array.v` 增加结果锁存 + `row_sel`/`col_sel` 读出端口
- **验证**：随机读取各行列验证正确性
- **复杂度**：低
- **预计**：1 小时
- **状态**：✅ 完成

### 1.3 状态与错误输出
- **目标**：增加 `overflow` 标志、`cycle_count` 计数器、`error` 信号
- **改动**：`systolic_array.v` 增加状态寄存器
- **验证**：检查各状态下的信号值
- **复杂度**：低
- **预计**：1 小时

### 1.4 连续计算模式
- **目标**：支持 back-to-back 矩阵乘法，无需等待 IDLE
- **改动**：FSM 增加 `S_RELOAD` 状态，DONE 后检测到新 valid 直接开始下一轮
- **验证**：连续喂 3 组不同矩阵，验证每组结果独立正确
- **复杂度**：中
- **预计**：2 小时

## Phase 2: 性能提升

### 2.1 双缓冲 (Double Buffering)
- **目标**：一组数据在计算，另一组同时加载，消除加载等待
- **改动**：增加两组输入缓冲，交替切换；FSM 增加 buffer 选择
- **验证**：对比单缓冲和双缓冲的吞吐量（cycles per matrix）
- **复杂度**：中
- **预计**：3-4 小时

### 2.2 PE 内部流水线化
- **目标**：拆分 PE 内的乘法和累加为两级流水线，提高最大时钟频率
- **改动**：`pe.v` 增加一级流水线寄存器
- **代价**：K_DIM 额外 1 周期延迟，需要调整对齐
- **验证**：时序分析 + 功能仿真
- **复杂度**：中
- **预计**：2-3 小时

### 2.3 性能计数器
- **目标**：统计实际计算周期数、PE 利用率、空闲周期数
- **改动**：增加计数器寄存器 + 读出接口
- **验证**：对比理论值
- **复杂度**：低
- **预计**：1 小时

### 2.4 时钟门控 (Clock Gating)
- **目标**：空闲 PE 关闭时钟，降低动态功耗
- **改动**：PE 增加 clock enable，idle 行/列关时钟
- **验证**：功能不变 + 功耗对比（需要综合工具）
- **复杂度**：中
- **预计**：2 小时

## Phase 3: 功能扩展

### 3.1 转置模式
- **目标**：支持 `A × B`、`A^T × B`、`A × B^T`、`A^T × B^T` 四种模式
- **改动**：增加 `transpose_mode` 配置信号，调整边界输入的数据顺序
- **验证**：四种模式分别测试
- **复杂度**：中
- **预计**：2-3 小时

### 3.2 矩阵加法模式
- **目标**：复用 PE 阵列做 element-wise 加法 `C = A + B`
- **改动**：PE 增加 `mode` 选择（MAC / ADD），FSM 简化为单周期
- **验证**：加法模式正确性
- **复杂度**：低
- **预计**：1-2 小时

### 3.3 向量-矩阵乘法
- **目标**：`y = v × M`，其中 v 是 1×K 向量，M 是 K×N 矩阵
- **改动**：只用第一行 PE，其余行旁路
- **验证**：对比标准矩阵乘法结果
- **复杂度**：低
- **预计**：1 小时

### 3.4 权重驻留模式 (Weight Stationary)
- **目标**：把 B 矩阵预加载到 PE 的累加器/寄存器中，只流式输入 A
- **用途**：CNN 卷积层推理（权重固定，输入流式）
- **改动**：PE 增加 `weight_load` 模式，FSM 增加 `S_LOAD_WEIGHT` 状态
- **验证**：加载权重后多次流式输入不同 A，验证结果
- **复杂度**：高
- **预计**：4-5 小时

### 3.5 分块计算 (Tiling)
- **目标**：大矩阵自动拆分成阵列能处理的小块，分批计算后拼接
- **改动**：上层 wrapper 负责分块、调度、结果拼接
- **验证**：16×16 矩阵用 4×4 阵列计算
- **复杂度**：高
- **预计**：5-6 小时

## Phase 4: 系统集成

### 4.1 AXI-Stream 数据接口
- **目标**：输入输出走 AXI-Stream 协议，支持 `tvalid`/`tready`/`tlast`
- **改动**：增加 AXI-S master/slave wrapper
- **验证**：Cocotb + AXI 协议检查
- **复杂度**：中
- **预计**：3-4 小时

### 4.2 AXI-Lite 配置接口
- **目标**：运行时通过寄存器配置矩阵大小、模式选择、状态读取
- **改动**：增加寄存器映射 + AXI-Lite slave
- **验证**：读写寄存器验证
- **复杂度**：中
- **预计**：3-4 小时

### 4.3 中断控制器
- **目标**：计算完成、溢出等事件触发中断
- **改动**：增加 IRQ 输出 + 中断状态/使能寄存器
- **验证**：中断触发/清除流程
- **复杂度**：低
- **预计**：1-2 小时

### 4.4 DMA 集成
- **目标**：与 AXI DMA 配合，CPU 配置一次后全自动搬运数据
- **改动**：需要外部 DMA IP，本项目提供连接 wrapper
- **验证**：端到端仿真（CPU → DMA → Array → DMA → CPU）
- **复杂度**：高
- **预计**：需要外部 IP，本项目只做 wrapper

## Phase 5: 高级特性

### 5.1 定点数支持 (Fixed-Point)
- **目标**：支持 Q 格式定点数（如 Q8.8、Q4.12）
- **改动**：PE 内部调整乘法和移位逻辑
- **验证**：定点精度测试
- **复杂度**：中
- **预计**：3-4 小时

### 5.2 半精度浮点 (FP16)
- **目标**：IEEE 754 半精度浮点 PE
- **改动**：替换 PE 内的乘累加为 FP16 MAC 单元
- **验证**：浮点精度测试（对比软件 FP16 结果）
- **复杂度**：高
- **预计**：8-10 小时

### 5.3 BFloat16 支持
- **目标**：Google BFloat16 格式（与 FP32 同指数范围，训练友好）
- **改动**：类似 FP16，调整指数/尾数位宽
- **复杂度**：高
- **预计**：6-8 小时

### 5.4 多阵列并行
- **目标**：多个子阵列并行计算，提升吞吐量
- **改动**：顶层 wrapper 管理多个 systolic_array 实例
- **验证**：线性加速比测试
- **复杂度**：高
- **预计**：6-8 小时
